Information Security Overview

DeepTech Sp. z o.o. · Draft v0.9 · September 2026

Public summary of the security controls protecting the Audomate platform, hosted on Google Cloud in EEA regions only.

1. Network security

  • TLS 1.3 on all external connections; TLS 1.2 enforced as minimum — no unencrypted channels.
  • Mutual TLS (mTLS) between internal services via managed service mesh.
  • Web Application Firewall in front of the API gateway — OWASP Top-10 protection, adaptive DDoS mitigation.
  • Data layer (database, object storage, cache) on private networking with no public IP addresses.

2. Identity and access

  • SSO via SAML 2.0 / OIDC through an EU-region identity provider; integration with client IdPs (e.g. Microsoft Entra ID); MFA mandatory.
  • Access tokens with 15-minute TTL and refresh-token rotation.
  • Role-based access control at application level; database row-level security as an independent second enforcement layer — cross-tenant access is structurally impossible.
  • Secrets in a managed vault with access auditing; rotation every 90 days.

3. Data protection

  • Encryption at rest: AES-256 across database (customer-managed keys via Cloud KMS), object storage and vector indexes; key rotation every 90 days with failure alerts.
  • Point-in-time recovery on the primary database; object storage replicated dual-region within the EEA. RPO 1–4 h, RTO 4–8 h by plan tier.
  • Hard deletion on request: a purge pipeline removes vector, relational and object-storage records.

4. AI-layer security

  • LLM inference on enterprise EEA endpoints under contractual zero-data-retention terms; no client content used for training.
  • Prompt-injection detection and input sanitisation before any model call; per-tenant session isolation; per-tenant token budgets.

5. Logging and monitoring

  • Immutable, hash-chained audit log of every user action, AI verdict and human override.
  • Centralised monitoring with error-rate and latency dashboards; syslog / REST forwarding to client SIEM available.

6. Incident management

Severity-based response with on-call escalation: critical incidents — tenant isolation, CTO/CEO escalation within 15 minutes, affected-client notification within 30 minutes (Enterprise) or 24 hours (Standard/Pro); personal-data breaches notified per GDPR art. 33 within 72 hours to the authority and within 24 hours to affected clients. See the Incident Response Summary.

7. Secure development

Pending confirmation from engineering: code review policy, dependency and vulnerability scanning cadence, pre-release testing practice, critical-CVE patch SLA, personnel security training.

8. Certifications

Hosting layer (Google Cloud): ISO 27001, SOC 2, CSA STAR — inherited infrastructure controls. DeepTech organisation: ISO 27001 in preparation (target: H1 2027); independent penetration test planned for Q1 2027 vendor selection in progress.
