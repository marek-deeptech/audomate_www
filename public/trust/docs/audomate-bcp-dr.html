Business Continuity & Disaster Recovery Summary

DeepTech Sp. z o.o. · Draft v0.9 · September 2026

1. Architecture for availability

  • Stateless services on serverless containers, minimum two concurrent instances, autoscaling, zero-downtime rolling deploys.
  • Primary database in HA configuration with a standby replica in a separate zone; automatic failover under 30 seconds.
  • Object storage dual-region within the EEA (europe-west1 + europe-west4) with geo-redundancy.
  • Job queue (Redis) in HA configuration — asynchronous processing survives single-node failure.
  • Frontend on EEA edge network with automatic PoP failover.

3. Degraded modes

  • LLM endpoint outage or latency spike: asynchronous queue holds jobs, automatic retry, degraded-mode processing; target restoration for this scenario under 4 h; users notified on completion.
  • Regional cloud outage: failover to the DR region (europe-west3); RPO/RTO per the table above.
  • Management-plane vs data-plane separation: whether a console outage can affect processing — to confirm.

4. Backups and restore

  • Point-in-time recovery on the primary database; encrypted backups within the EEA.
  • Backup retention window: to confirm.
  • Last restore test: date and scope to confirm — scheduled before Trust Center launch.

5. Incident communication

Named client contacts are notified per the Incident Response Summary; written report within 24 h for P1/P2; post-incident review within 5 working days.
